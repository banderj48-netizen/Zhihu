# 知乎领域出题流水线

知乎适合作为公开社区观点和案例来源，不把社区回答当作用户本人立场。传统后端持有授权、调用知乎适配器、保存原始响应和删除记录；Agent 只接收脱敏证据片段。

1. 根据用户选择的叶子领域生成查询词（同义词、前沿词、争议词），同时设定时间窗、语言和数量上限。
2. 通过知乎开放平台搜索获取标题、摘要、URL、作者、编辑时间、赞同/评论数和权威等级；必要时调用问题推荐和问题回答摘要。保留带 `utm_source=openapi_platform` 的原始 URL、响应哈希和抓取时间。
3. 摘要不是全文，编辑时间也不保证是首次发表时间；因此只把它当候选证据。高风险事实必须用官方文档、论文、标准或其他一手来源交叉核验。赞同数、排名和权威等级不能单独代表真伪。
4. 按规范化 URL、内容 ID、文本哈希去重，分离事实陈述、经验叙述、价值立场和未证实推测，保留相互冲突的观点与来源。
5. 生成四类题：有证据答案的知识题；考察取舍的应用题；记录条件、理由和例外的立场题；带发布日期、证据缺口和争议说明的前沿题。公开 DTO 不包含正确答案和裁判提示，避免泄露。
6. 规则闸门检查敏感属性推断、诱导性措辞、明显暗示答案、重复、时效和可追溯引用；保存题目版本、证据版本、rubric 和生成模型/提示版本。
7. 用户回答后分别写入 `knowledge_score`、`stance_record`、`reasoning_observation`；“不知道/不适用/都不符合”；其他情况选择自定义选项并填写 custom_text是合法结果。立场没有对错，知识题的评分允许 `uncertain`。
8. 只把多次一致、来源充分的回答生成 `memory_proposal`，默认 private/unconfirmed，由传统后端版本化写入并交给后续 RAG 服务。Agent 不实现切片、embedding、向量库或 RAG 检索；撤销来源由传统后端发布删除事件，RAG 消费者负责清理自己的索引。

当前知乎开放能力的限制：OAuth 可以读取基本资料，但不能让应用任意读取登录用户的回答全文；个人创作全文接口只对应开发者自己的 Access Secret。首版个人导入因此仍限于已授权的个人简介和回答可用摘要/用户主动提供内容，不能承诺任意用户全文抓取。知乎 CLI/API 失败、限流或配额耗尽时，任务应记录可重试错误，不伪造题目。

## 选择题约束
所有领域题必须是选择题。每题提供 3–5 个预设选项，并固定提供“其他/自定义答案”；选择该项时必须填写 `custom_text`。可另设“不知道/不适用/都不符合”。Agent 保存原始选项 ID 和版本，分离记录立场与知识掌握，不把开放式回答作为默认题型。


## 目标优先级（修订）
题目不是通用知识测验，而是从真实争议中识别用户会采取的立场、权衡标准、风险边界和论证方式。知识掌握程度只作为辅助字段。采用信息增益策略动态减少题数：当候选观点的区分度达到阈值即停止。
