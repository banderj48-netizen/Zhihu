# 领域情景题生成

本模块不实现 RAG。用户回答只生成供后续 RAG 服务消费的 `memory_proposal`，由其他服务负责切片、向量化和索引。

领域选择 → 传统后端按叶子和时间范围检索公开知乎摘要/回答摘要及已授权用户证据 → 规范化 URL、作者、时间、摘要哈希并去重 → 用权威文档/论文交叉核验事实、保留多种立场 → 生成版本化候选题（事实知识、应用权衡、立场情境、前沿争议四类）→ 校验诱导、答案泄露、敏感推断、重复和时效 → 发布不可变题目。知识题带 server-only 正确要点、评分 rubric、证据和不确定性；立场题没有正确答案，记录 position、理由、条件、例外和信心；应用题同时记录推理质量与结论。允许“都不符合/不知道”，并固定提供“其他/自定义答案”。回答不会自动改变 Big Five；只有重复且有证据的行为才产生待审核记忆提案。用户答案分离 stance_record 与 knowledge_score，候选记忆默认 private/unconfirmed，生成供后续 RAG 消费的 memory_proposal（Agent 不实现 RAG）；来源撤销时清理向量、缓存、题目和版本。

Agent 不直接调用知乎 OAuth；知乎访问由传统后端的 ZhihuAdapter 完成。

## 选择题约束
所有领域题必须是选择题。每题提供 3–5 个平衡措辞的预设选项，并固定追加“其他/自定义答案”；选择该项时必须填写 `custom_text`。可另设“不知道/不适用/都不符合”，不把空白当答案。服务端保存 `selected_option_id`、题目版本和自定义文本，再分别生成 stance_record、knowledge_score、reasoning_observation；输出 memory_proposal 供后续 RAG 服务消费。本模块不实现切片、embedding、向量库或 RAG 检索。


## 核心目标与出题标准（修订）
目标是用尽可能少的题还原用户在该领域会发表的观点、立场、价值排序、证据标准和边界条件；知识掌握仅为辅助信号，不把题目设计成普通知识考试。

题目必须来自真实争议、前沿分歧或具体取舍，选项代表现实中存在的不同立场，避免普遍正确、常识化或道德高地表述。每题至少承载两个可观测信号（例如风险偏好与证据标准），根据前题答案的信息增益决定是否继续提问。

全部采用选择题：3–5 个平衡预设选项，固定包含“其他/自定义答案”（需填写 custom_text），可包含“不知道/不适用/都不符合”。提交后优先生成 stance_record 和 reasoning_observation；只有出现可核验事实线索才生成 knowledge_signal，且允许 uncertain。输出 memory_proposal 供后续 RAG 服务消费，Agent 不实现 RAG。
