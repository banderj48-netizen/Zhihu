# Agent 后端开发策略

## 总原则

先实现确定性的数据边界，再接入模型。传统后端是权限、持久化和版本的唯一事实来源；Agent 是无状态或短状态的推理编排层。

Agent 不直接访问数据库、知乎 API、对象存储或用户 Token。所有外部数据通过 `contracts` 定义的输入传入，所有画像变化通过事件或提案返回。

## 开发阶段

### 阶段 1：契约优先

先定义画像快照、证据片段、记忆、策略、初始化任务和 Agent 输出 DTO。使用固定 JSON fixture 做联调，不依赖真实知乎和真实 LLM。

验收：字段稳定、版本可识别、私密数据过滤可测试、旧客户端能拒绝未知版本而不是静默误读。

### 阶段 2：纯规则能力

实现领域分类、三层记忆判定、检索排序、隐私过滤、上下文预算和 `chara_card_v2` 映射。此阶段可使用假数据和规则，不调用模型。

验收：同样输入得到可重复结果；`share=false`、撤销来源和拒绝内容永不进入上下文。

### 阶段 3：模型适配

接入 LLM 和 Embedding 适配器。模型只生成结构化候选或回答，不直接写正式画像。保存模型、提示词版本、请求 ID 和输出校验结果。

验收：模型超时、格式错误、限流和编造风险都有明确错误或降级路径。

### 阶段 4：初始化闭环

接入传统后端的初始化任务、个人简介/回答证据、候选抽取、一次性总确认和版本生成。

验收：用户可以跳过性格测评和总确认；跳过时仍可生成私有低置信画像，未确认内容可被 Agent 使用但带不确定性。

### 阶段 5：持续校准

加入卡壳信号、用户纠正、历史题重演、证据队列和人格变化提案。所有变化先回传传统后端，不能在 Agent 内部直接修改正式版本。

## 代码落位

- `backend/agent/contracts`：跨边界 DTO、事件、版本和错误码。
- `backend/agent/adapters`：LLM、Embedding、画像快照、检索和事件回传接口。
- `backend/agent/retrieval`：查询分析、混合检索、排序和上下文截断。
- `backend/agent/prompting`：固定上下文、动态记忆和角色卡投影。
- `backend/agent/runtime`：对话回合、输出校验、卡壳检测和降级。
- `backend/agent/personality`：测评计分、效度和解释提案。
- `backend/agent/domains`：领域识别和情景题候选。
- `backend/agent/memory`：三层记忆分类和召回规则。
- `backend/agent/evaluation`：离线 fixture、回归和人工评测。

传统后端的 API、数据库、OAuth、任务队列和审计实现不放入本目录。
