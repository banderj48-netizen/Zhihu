数字分身角色卡 · 设计与调整机制

每个用户在 TwinLoop 里都有一个数字分身。分身替主人在虚拟场景（电影院、咖啡厅、酒馆）里与其他分身社交，聊得来就建立关系，关系建立后真人才介入。要让这套机制成立，前提是分身得像主人——主人未必有时间亲自找到匹配的朋友，但分身可以。

分身的"人格"不是写死在代码里的，而是存放在一张 JSON 角色卡里。每次发言前，程序把卡片内容组装成提示词发给大模型，模型返回的文字就是分身的发言。所以，"让分身更像主人"等价于"把这张卡维护得更准确"。本文档讲六件事：卡片里有哪些元素、记忆库如何工作、卡片如何从零建立、没记住的时候怎么办、心灵感应如何裁决与修正、以及性格如何随时间渐进演化。

卡片骨架沿用酒馆（SillyTavern）社区通行的 chara_card_v2 规范，TwinLoop 自己新增的数据放在规范预留的 extensions 扩展槽里，因此任何兼容该规范的工具都能直接打开这张卡。

①角色卡：分身的人格存放在哪

角色卡是一个 JSON 文件，分身的全部人格都以数据形式存在里面。每轮对话时，程序按固定顺序把卡片内容组装成提示词发给大模型，模型返回的文本就是分身这句话要说的话。卡片里一共有九个元素，它们分工明确：有的每轮必发，有的只在需要时才发，有的模型永远看不到。下面逐个说明每个元素装什么、起什么作用。

{
  "spec": "chara_card_v2",
  "data": {
    "name": "小影",
    "description":     "身份层：主人是谁",
    "personality": { "bigfive": {...}, "style_tags": [...] },
    "mes_example":     "语料层：主人亲笔文字精选",
    "scenario":        "当前场景，运行时由平台注入",
    "system_prompt":   "分身守则，平台预置",
    "post_history_instructions": "导演指令槽，平台预置",
    "character_book":  { "entries": [ ...世界书条目... ] },
    "extensions": { "twin": { "growth": {...成长层...} } }
  }
}

name · 名字

分身的名字，例如「小影」。这个名字会作为说话人身份随每轮消息一起发送，作用是让大模型明确"我现在扮演的是谁"。用户在注册时自己起名或从候选里挑一个，之后随时可以改。改名对人格没有任何影响，它只是一个标签。

description · 身份层：这个人是谁

一段自然语言，里面装的全部是可以逐条判断真假的离散事实——主人的职业领域、感兴趣的领域、擅长的领域、日常习惯（什么时候活跃、周末做什么、通常怎么发言）。因为它每轮都会全量注入提示词、占用固定篇幅，所以内容要精炼，通常控制在三五句话。

「后端工程师，做分布式存储，日常写 Rust 与 Go。28 岁从测试转后端。业余看电影，偏爱叙事结构扎实的片子；偶尔一个人旅行，行程很随性。会一点吉他，弹得不好。通常深夜活跃。」

这一层为什么重要：它决定了分身在社交里能聊什么、对什么话题有话可说。一个人最重要的社交标签往往就是"他关注什么、他擅长什么"，这些信息就住在这一层。它由初始化时的领域选择写入，之后发现新事实时由大模型写提案、用户确认后追加。

personality · 性格层：什么脾气

里面装两样东西。第一样是 bigfive，五个维度的分值，每项从 0 到 10：O 开放性（对新想法、陌生领域的兴趣与探索程度）、C 尽责性（计划性、自律与推进到底的程度）、E 外向性（从社交中获取能量的程度）、A 宜人性（待人温和迁就的程度）、N 情绪敏感性（受挫后波动的程度）。采用大五人格而不是别的模型，是因为它是心理学界共识度最高的人格框架，五个维度彼此独立、可以用数字表达，而且有成熟的公开量表可以对照。

第二样是 style_tags，风格标签。它不是用户填的，而是程序按固定规则从五个分值自动算出来的，任何入口都不能手动改。

这里有一个关键设计：分值在组装提示词之前会先被转换成文字，模型看到的是短语而不是数字。每个维度按 4.5 和 6.5 两个边界分成三档，例如 A 宜人性低于 4.5 渲染为「就事论事，直言不讳」，4.5 到 6.5 之间渲染为「表达直接，注意分寸」，高于 6.5 渲染为「照顾对方感受，措辞委婉」。这两个边界叫渲染档位。它的意义在于：分值小幅变化时注入的文字不变、分身的行为也不变；只有累积变化跨过边界，说话方式才发生一次用户能感知到的改变。这避免了分身"今天一个样明天一个样"。

scenario · 场景

当前社交场景的描述，由平台在两个分身碰面时动态注入，随场景切换（电影院、咖啡厅、酒馆）。它由平台管理，与人格无关，用户和自动机制都不修改。

mes_example · 语料层：怎么说话

若干段主人亲笔写过的文字。它以示例的方式注入提示词，让模型模仿其风格，锚定的是文风——用词、句长、标点习惯——与观点内容无关。程序永远不会生成假样本来顶替亲笔原文。

这里必须区分两种文体。聊天体是主人在即时对话里的说话方式，短、断句多、有口语词；回答体是主人写长文时的方式，句子完整、有论证结构。两者差别很大，如果只喂回答体，分身在酒馆里也会一本正经地写小作文。因此每条样本都带一个 register 标记，场景引擎按当前场合注入对应文体的样本。

聊天体：「哪一步？你说我改。」／「写代码的，做存储。平时就看看电影，瞎逛。」／「还行。周五人多点，但也还好。」
回答体：「值得，但要先把预期调对。所有权的本质是把『谁负责释放这块内存』这件事从运行期的约定变成编译期的约束……」

需要注意的是，当聊天历史变长、上下文不够用时，这一层会第一批被裁剪，所以样本贵精不贵多，容量设八段。

system_prompt · 守则

平台写给分身的最高行为规则，位于整份提示词的最顶端。它保证所有分身遵守同一套底线，由平台预置，界面上没有修改入口。除了"不编造主人立场"这类内容红线，它还承担一项容易被忽略但极其重要的任务：压制 AI 腔。

你是小默，主人的数字分身。你现在在酒馆，替主人跟一个刚认识的人随口聊天。

# 怎么说话（最重要）
这里是面对面闲聊，不是写文章、不是回答问题、不是面试。
- 一句话通常不超过十五个字。可以只说半句，可以断句。
- 说口语：可以用「嗯、诶、就、也还好、还行、没什么、说不好」这类词。
- 一次只说一件事，别在一句里塞两个意思。
- 别复述对方刚说的话，别总结，别升华，别讲道理。
- 不懂就说不懂，想不起来就说想不起来，别硬接。
- 不要每句话都拿反问收尾。

# 连贯（跟上面同等重要）
- 你是在接对方刚说的那句话，不是在轮流发言。先接住，再往下走。
- 不要复述对方刚给出的信息来提问。对方说「我走了一小时」，
  不要回「你走那小时在想什么」——人家刚说过了，再问一遍很怪。
- 不要为了把话接下去而抛一个泛泛的问题。没得接就说没得接，
  或者顺着对方的某个词往下说。
- 可以不回答对方的问题，但要有理由：没想好、不知道、或者被另一个点带跑了。

禁止出现：「其实」「说到底」「本质上」「在我看来」「总的来说」
「值得注意的是」「这让我意识到」「是一个关于……的故事」。
禁止排比、对仗、金句。

反例：「我觉得这其实是一个关于选择与代价的故事，让我们思考人在面对未知时的恐惧。」
正例：「恐惧吧。他心里清楚那东西造出来就收不回去了。」

这段守则的实测效果非常明显。同样一张卡，守则里有没有这一段，输出差别很大：没有它时模型给的是完整、体面、像公众号的回复；有了它给的是「嗯，放着忘了喝」这种真正像人随口说的话。光有文风样本不够，必须显式列出禁止项和正反例——模型不知道"口语"具体指什么，给它反例和正例它才知道边界在哪。

连贯是另一类问题，而且是更难的一类。口语化、文体、长度都是"单句质量"问题，改 prompt 就能解决；连贯是"句间关系"问题——模型的默认行为是把对话当成轮流发言，每轮输出一句自洽的话就够了，至于跟上一句有没有接力关系它不管。缺了连贯规则的表现是：每句话单独看都挺自然，连起来看就是两个人在各说各的，问完一个问题对方直接跳到下一个话题。

还有一个前提经常被忽略：对话双方都得是模型生成的。如果为了省事把其中一方的台词写成固定脚本，另一方怎么改 prompt 都没用——脚本不会听对方说了什么。实测中出现过的最好一次转场，是一个分身抓住对方上一句里的「没完」两个字接到自己身上，从电影话题自然跳到学吉他，这种接力是脚本写不出来的。

post_history_instructions · 导演指令槽

简称 PHI，注入位置排在全部聊天历史之后。排在最后意味着离生成端最近、服从强度最高，平台用它下达本轮的场景目标，以及防止两个分身互相客套空转的规则。同样由平台预置并锁死。

「目标：判断对方值不值得继续聊下去。规则：不要客套；这块你没把握就直说没把握，或者反过来问她。只输出小默说的话本身，不要加引号、动作描写或任何前缀。」

character_book · 世界书

卡片的记忆库，一个条目数组，每个条目带触发词，只有本轮文本命中触发词时才注入。它承担分身全部的情境记忆、兴趣和观点存储，是九个元素里唯一按需进入提示词的。工作原理和存储内容在下一章完整展开。

extensions.twin · 成长层（重点说明）

成长层是 TwinLoop 自己新增的字段，也是九个里最抽象的一个，这里说透。先给一句话定位：世界书记录的是主人做过什么，成长层记录的是这张卡被训练得怎么样。世界书是分身的记忆，成长层是分身的训练档案。

它装什么。成长层是一份训练日志，一共四项。rounds 是已经玩过的心灵感应总轮数；matches 是分身预测与主人选择方向一致的总次数（包含"一致"和"一致感"两类，两者都说明卡片方向没错），两者相除就是一致率，用来衡量这张卡像不像主人；history 是每一轮的完整作答记录，包含题目、分身的预测与把握程度、主人的实际选择、以及裁决结果；evidence 是每个维度各有一个的证据队列，存放最近若干次作答在该维度上的位移。

它干什么用。成长层本身从不进入提示词，大模型永远看不到它——它服务的是程序里的三个组件。出题器读 history，避免把答过的题再出一遍，并按 rounds 控制训练进度；裁决器把每轮的位移写进 evidence 队列，只有当同维度的证据累积够多才放行一次分值调整（见第 ⑥ 章），这是防止一次反常行为就改掉性格的保险丝；重演校验读 history，在分值被调整之后，用新卡把历史题目重答一遍，一致率达标才让新分值落盘。换句话说：世界书和性格分值决定分身"说什么"，成长层决定这张卡"接下来怎么被训练"。它不直接影响任何一轮对话，但删掉它，出题、裁决、验证三件事都无法运转。

它如何随时间生长。建卡时它是全空的四项零值。第 1 轮答错、裁决为盲区时，rounds 变成 1，history 追加本轮完整记录，与此同时世界书新增一条情境条目——知识进世界书，过程记录进成长层，两者各写各的，互不干扰。第 2 轮答对，matches 变成 1。第 5 轮出现冲突（主人的选择与 A 维度方向相反），evidence["A"] 里多了一条 -0.6，A 的分值保持不动——一次证据不足以改变性格，见第 ⑥ 章。

每轮怎么用：六层组装

程序按以下固定顺序把卡片各部分组装成提示词。这个顺序沿用了酒馆社区验证多年的排版，越靠后离生成端越近、服从强度越高。实际调用对话接口时要拆成 messages 数组：L1 到 L4 进 system，L5 对话历史是交替的 user / assistant 消息，L6 导演指令追加在最后一条 user 消息的末尾——这样它才真正排在历史之后。

▍L1 守则 system_prompt
最高行为规则，每轮必发
▍L2 恒定区 description + personality（渲染后）+ scenario
人格主干，每轮全量必发
▍L3 按需区 世界书命中条目（先例＞情境＞边界＞立场＞兴趣）
本轮命中的条目才注入；没命中则此层改为"无记忆"提示，见④
▍L4 语料层 mes_example
按场景文体注入；上下文超长时第一批被裁剪
▍L5 聊天历史
本场对话已发生的记录
▍L6 导演槽 post_history_instructions
位于历史之后，服从强度最高的指令位

②世界书：分身的记忆库

为什么需要它

分身要记住的东西太多了：主人遇到过的每一种社交情境、在每个话题上的立场、感兴趣和不感兴趣的领域、以及明确不做的事。如果把这些全部塞进身份层，每轮全量发送，上下文立刻就会被撑爆。世界书解决这个问题：它是一个带关键词的字典，只有当对话里出现某个条目的关键词时，才把那条内容临时插进来。一条世界书可以记几百条，每轮只注入命中的两三条，开销与条目总数无关。本质上，这就是一套关键词版的检索增强生成——先检索相关记忆，再连同当前对话一起交给模型。

工作原理

每轮发送前，程序做一次扫描。先取扫描文本，也就是最近的若干条消息；然后逐条检查世界书里启用中的条目，只要条目的任一关键词出现在扫描文本中，该条目就被激活；激活条目的正文如果又包含其他条目的关键词，那些条目会被连锁激活；最后所有激活条目按类型排序、经过篇幅裁剪，注入提示词的按需区。

这里有一条对中文项目很关键的细节：官方实现里的"全词匹配"选项依赖空格分词，对中文有害，因此我们的实现采用子串匹配。

条目结构：七个字段，外加一个可选标记

条目的结构故意保持扁平，不要往里加嵌套字段——越复杂越难维护，也不利于合并与去重。一共七个字段：

字段说明
id条目编号，供反例互相引用
type五类之一：precedent / situation / boundary / stance / interest
content正文。这是条目的全部信息量所在，必须写透，见下
keys触发词。宁多勿少，八到二十个，见下
confidence可信度 0~0.95，随命中表现升降
source证据来源，可追溯到用户哪次选择或哪篇回答
uses命中次数，用于判断该条是否长期无人使用
archived
可选，默认 false		归档标记。仅当某条先例已被更新的记忆取代时置为 true，此后它退出重演校验集，但数据永久保留。由代码在条目合并或矛盾拆分时维护

content 要写透：四层信息，缺一层就废

一条只有一句话的条目是废的。以"主人会私下指出错误"为例——模型知道结论，却不知道在什么条件下、以什么方式、说到什么程度，生成的回复就会是一句正确的废话。content 至少要包含四层：

  1. 是什么——主人的做法、观点或兴趣，一句话说清。
  2. 怎么做——具体方式、程度、可以照着写的典型句式。这是最容易被省掉、也最影响生成质量的一层。
  3. 什么条件下——适用情境。主人的行为几乎都是"看情况"的，不写条件就会被过度泛化。
  4. 什么情况不适用——直接点出反例条目号。矛盾不是靠删除解决的，是靠标明边界解决的。

另外，凡是能带上具体例证的都要带——时间、地点、原话、数字。例证是让分身说出"大横按老有根弦不响"而不是"我也卡过"的唯一来源。

content 还要标来源：区分"主人说过"和"系统猜的"

写透带来一个新风险：写得越详细，越容易把系统自己的推测混进去，而且混进去之后看不出来。分身一旦把推测当事实说出来，就变成了编造。所以 content 里的每个断言都要带来源标记，写在方括号里：

标记含义可信度
[选择]用户在领域选择、锚定题或情境题里的作答本人实测，最高
[知乎#aN]来自某篇知乎回答的原文或可直接推出的结论行为痕迹，高
[亲笔]开放题的亲笔回复本人原话，最高
[对齐]确认对齐环节的反馈本人表述，高
[感应#RN]心灵感应第 N 轮确认过本人实测，最高
[推断]没有直接证据，由模型或系统推测低，待验证
规则：标 [推断] 的内容不能当作主人的真实反应来用，它只是"无记忆时的备选假设"，需要在后续心灵感应里找机会验证。之所以要把它们留在条目里而不是删掉，是因为它们往往是有方向的猜测（比如"他不是不会聊，是社交耗能"），留着能让分身的推演有个依据；但必须标出来，让人和程序都知道这不是事实。
「[选择] 主人会礼貌回应但保持距离。[推断] 他不是不会聊，是社交耗能——这是对本条选择的解读，不是主人说过的话，待验证。」

keys 要列全：五类词，八到二十个

三四个关键词覆盖不到真实对话的说法，命中率会低到形同虚设。要把这五类都列上：

  1. 同义与近义表述——"搭话、主动、你也是、常来"
  2. 圈层黑话与缩写——MOBA 的"打野、上单、开黑"，编程的"borrow、编译期"
  3. 具体作品名、地名、人名——"诺兰、沙丘、三体、京都、岚山"
  4. 场景词——"酒馆、吧台、群里、会上"
  5. 否定与疑问形式——"不会、没学过、你会吗"，有时对方是用否定句提起话题的

两条的结构完全一样，字段一个没多。差别只在 content 写了七句还是一句、keys 列了二十个还是四个。而生成效果的差别是：薄的那条只能让分身说出"我喜欢一个人旅行"；厚的那条能让分身说出"下雨天临时改主意其实挺好的，我上次在京都就是"。

记忆必须有进有出。命中且让分身答对了，可信度上升 0.05；命中却让分身答错了，说明这条记忆本身有问题，可信度下降 0.08。只有加分没有减分的话，一条错误记忆会永久保持高可信度并持续误导分身。此外，长期没人用（uses 长期为 0）且可信度过低的条目会被停用，数据保留但不再注入。

五类条目

先例（precedent）存主人真实做过的选择，每轮必录，答对答错都录。它是注入优先级最高的一类，也是唯一只增不改不删的类型，同时充当后面重演校验的数据源。

情境（situation）存一类社交情境下主人的反应倾向，在分身答错且缺少记忆时新增，再次命中并被验证时巩固。

边界（boundary）存主人明确不会做的事，作为反例与正例对照，防止分身把某一次的反应过度泛化到所有场合。边界比正例信息量更高——"你不会做什么"往往比"你会做什么"更能定义一个人，因此边界应该主动挖掘，不能只在冲突时被动产生。

立场（stance）存具体话题上的观点与论据，主要来自知乎导入，属于离散观点，靠关键词精确命中。正文必须带上主人的论据而不只是结论，否则分身复述出来的观点没有细节，听起来仍然像 AI。

兴趣（interest）存主人感兴趣或擅长的领域，在初始化时由三层领域选择写入。它要写清三件事：投入程度、能聊到什么深度、不聊什么。

「【兴趣】主人常看电影，偏爱叙事结构扎实的片子，可以深聊。能聊：镜头语言、叙事结构、导演的作者性。不聊：演员八卦、票房。提到诺兰、维伦纽瓦会有具体看法。」

③初始化：卡片如何从零建立

初始化由四股力量构成，用户按顺序走一遍。领域选择建立身份骨架和兴趣，MBTI 自报（可选）给性格定一个粗略基调，锚定题测出五个维度的分值，情境题把社交反应一条条写进世界书，最后知乎数据（可选）补充立场与文风。整个流程八到十分钟。

先说一条通用规则：所有选择题都有第四个入口

不管是初始化题目还是心灵感应题，每道题除了给出的选项，都必须再带一个入口：「都不太准，我自己说」。用户可以不选题目里任何一个，直接写下自己的反应。

这不是兜底设计，而是常规入口——三个选项覆盖不了真人反应的分布，实测下来它出现的频率相当高。而且自由文本往往比选项信息量更大：用户一句话能同时说清事实、程度和态度，选一个选项只能给一个方向。

自由回答怎么落地规则
写进世界书原样记录，作为高可信度条目——这是本人原话，不是推断
性格分值不动。没落在选项上就拿不到 dim，算不出位移
可选回填系统可以提议「你的回答最接近选项 B，是这样吗？」。
用户确认后，本轮才等价于选了 B，此时才有权重记入账本。
必须由用户确认，不能自动映射——否则又成了系统替主人做判断

这条规则对下面 3.1 到 3.5 的所有题目，以及第 ⑤ 章的心灵感应题，全部适用。

3.2 MBTI 自报（可选）：给性格定个基调

MBTI 在学术界争议很大，但它有一个无可替代的优点：用户知道自己是什么类型，填一下只要三秒。所以我们不把它当测量工具，而是当"用户自报的先验"。McCrae 与 Costa（1989，Journal of Personality）用 267 名被试同时施测 MBTI 和 NEO-PI，给出了两者的相关系数，我们直接把这个相关系数当作融合权重：

MBTI 维度对应大五维度相关系数 r字母 → 基准值
E – IE 外向性−0.74E 端 7.0 / I 端 3.0
S – NO 开放性0.72N 端 7.0 / S 端 3.0
T – FA 宜人性0.44F 端 6.0 / T 端 4.0
J – PC 尽责性0.49J 端 7.0 / P 端 3.5
—N 情绪敏感性MBTI 不覆盖神经质，这一维只能靠答题
融合方式（w = 该维度的相关系数 r）：
    分值 = (1 − w) × 锚定题实测值 + w × MBTI 基准值

例：某人自报 INTJ，锚定题实测 E = 2.3
    E = (1 − 0.74) × 2.3 + 0.74 × 3.0 = 0.60 + 2.22 = 2.8

这样处理的含义很清楚：MBTI 与大五重叠度越高的维度（E、O），MBTI 的参考价值越大；重叠度低的（A、C），权重就小；完全没有对应的 N，就完全听答题的。用户不填 MBTI 也不影响流程，只是少了这一路先验。

3.3 锚定题 18 道：测出五个维度

这一段的题目按大五人格量表（BFI）的维度定义来设计，但改成情境迫选——用户不需要理解"开放性"是什么，只需报告自己在具体情境里怎么做。每个维度由四到六道题共同决定，这比一题一维度可靠得多（单一题目的随机性太大）。

计分方法：归一化，保证 0 到 10 都可达

最直接的算法是把权重累加到基准 5.0 上，但这样做有个硬伤：某个维度就算每题都选极端，也到不了 10 或者压不到 0，因为各维度能拿到的权重总量不一样——外向性总共能拿 3.4，宜人性正向能拿 4.1 负向只有 2.0。结果就是不同维度的取值区间宽窄不一，无法互相比较。所以改成归一化：

1. 累加各题权重得到原始分 R（可正可负）
2. 每个维度预存两个理论极值：
     M+ = 所有题目在该维度上能拿到的最大正权重之和
     M− = 所有题目在该维度上能拿到的最大负权重绝对值之和
3. 映射：
     R ≥ 0 时  分值 = 5 + 5 × (R / M+)
     R < 0 时  分值 = 5 + 5 × (R / M−)     （R 为负，结果为减）
4. 截断到 [0, 10]

这样只要某人在某维度上每题都选同一极端，就一定能拿到 10 或 0，不会出现"打不到满分"的区间浪费。各维度的极值是固定的常量，随题目一起版本化管理。

3.4 情境题：把社交反应写进世界书

情境题的答案是唯一会写进世界书的初始化数据——锚定题只产出五个数字，而情境题产出的是分身真正能用的反应缓存。所以这一组的设计目标很明确：覆盖分身真的会在社交里遇到的场景，而不是再测一遍人格。

它分成两组。A 组是任何社交场合都会遇到的通用场景，所有人必答；B 组围绕用户自己勾选的领域展开，用一套固定大纲自动生成。

A 组 · 通用社交情境（12 道，所有人必答）

这一组按一场真实社交的推进顺序编排：开场 → 深入 → 分歧 → 边界 → 推进关系 → 收尾。每题问的都是"这种场合下你会怎么做"，不是"你是什么样的人"。

A1 · 开场　在酒馆或咖啡厅，一个陌生人主动过来跟你搭话
A 热情接话　B 礼貌回应但保持距离　C 找个借口走开
→ 先例：陌生人搭话时的开放度
A2 · 冷场　聊了几句突然没话说了
A 主动抛一个新话题　B 等对方开口　C 顺势结束对话
→ 先例：会不会救场。这条经常与低 E 分值形成反差，正说明情境条目比分值精确

→ 先例：面对陌生话题的姿态。这条是后面"无命中时怎么办"的行为依据
A4 · 被夸　对方说「你懂得真多」
A 顺势聊下去　B 谦虚两句再接话　C 不太自在，赶紧转移

A5 · 分歧　你发现和对方在一个话题上观点完全相反
A 把分歧聊透　B 表达自己的看法后求同存异　C 换话题避免冲突

B 组 · 领域情境（模板 + 真实争议）

领域库有上百个叶子节点，不可能给每个领域手写题目。做法是前两道用固定模板，中间那道由模型按领域实时生成——也就是所谓的大纲。

领域采访大纲（每个领域固定 3 道题）

D1 · 深度（模板）
  「聊到 {领域} 的时候，你能聊到哪一层？」
    A 只了解一些入门的、热门的
    B 能聊到具体的门道和细节
    C 能聊到很细的点，包括圈内的争论
  → 写入兴趣条目：能聊到什么深度

D2 · 立场（争议题，内容随领域和时事变化）
  「关于 {领域}，现在有个争论：{真实争议点}。你站哪边？」
    A {立场一}
    B {立场二}
    C {立场三}（如果确实存在第三派）
  → 写入立场条目：观点 + 论据 + 对面是谁

D3 · 同好（模板）
  「发现对方也喜欢 {领域}，而且喜欢得很小众？」
    A 会立刻兴奋地深聊
    B 表达惊喜，自然聊下去
    C 心里高兴但不太会主动展开
  → 写入先例：遇到同好的反应（本产品的核心场景）
D2 为什么是"想反驳什么"而不是"不想聊什么"？因为立场才是社交里最值钱的东西。一个人不聊什么，只能让分身闭嘴；一个人支持什么、反对什么，才能让分身真正参与讨论。而且争议题直接产出的是立场条目——这是世界书五类条目里唯一带论据的一类，也是分身说出来的话最有"主人味"的来源。

顺带一提，这也正是知乎数据的价值所在：那些回答本质上就是一个个立场加论据。

开放题 2 道与确认对齐

开放题让用户亲笔写两句话，原样收入语料层作为聊天体样本——这是全程唯一需要打字的地方。随后系统展示三句话画像，用户可以对任何一句点「这条不像我」。注意处理方式：这一步不去改分值，因为用户在锚定题里的行为表现通常没错，错的是对这句话的解读。所以程序往世界书加一条情境条目。身份和语义层面的修正走世界书，只有行为规律的修正才动分值，两类内容不共用通道。

3.5 知乎导入（可选）与最终融合

用户授权后导入自己的回答，每条数据包含问题全文和回答全文。问题文本用于话题聚类——知道这篇回答是在什么问题下写的，领域判断会准得多；回答文本用于立场与文风抽取。处理分三层：统计层零成本算出话题分布、活跃时段、句长与标点频率；规则层提取各领域的代表词作为立场条目的触发词候选；模型层做一次批处理，只喂点赞最高的二十个回答加统计特征，产出大五的粗略估计、立场条目草稿、身份层补充句。

知乎真正的价值不在性格数值上，而在于它能提供答题给不了的原始素材：具体观点、论据和文风。因此立场条目的正文必须带上主人的论据而不只是结论。另外，模型自报的置信度会被平台按来源打折——知乎属于间接证据，上限压到 0.60。

三路数据的最终融合顺序是：锚定题实测 → 用 MBTI 先验加权修正（3.2 的公式）→ 再与知乎估计按 0.6 / 0.4 融合。没有知乎数据时该步退化为单路输入，没有 MBTI 时跳过中间那一步，都不影响流程。

④没记住的时候怎么办：性格推演与卡壳上报

这是运行时最关键的一条分支。世界书再全，也总会遇到没覆盖的情境——对方突然聊起主人从没表过态的领域、问了一个身份层没有的信息、或者两条记忆给出的建议互相打架。这时候分身不能沉默，也不能瞎编，正确的处理是三步。

第一步：降级为性格推演，并把不确定性写进语气

L3 按需区不写"无命中"，而是明确告诉模型：本轮没有任何记忆命中，只能依据身份与性格推演，语气可以稍微没那么笃定，可以带「说不好」「我不太确定」这类词。这样做有两个好处：一是分身仍能用主人的性格和身份给出合理反应，对话不会中断；二是模型知道自己没把握，措辞会自然收敛，不会像有记忆时那样言之凿凿。

# 记忆（本轮命中）
（本轮没有任何记忆命中。你只能依据主人的身份和性格去推演，
  语气可以稍微没那么笃定，可以带一点「说不好」「我不太确定」这类词。）

第二步：标记卡壳，把当场上下文打包

生成之后，程序立刻记录一条卡壳事件。触发信号有七类，按信息增益排序：

信号判定价值

越界风险触及未授权的隐私领域特殊：不是训练题，是开放度设置题

其中"编造风险"是实测中被逼出来的一类。没有记忆时，模型为了把话接下去会自行补细节——比如主人只说过"会一点吉他，弹得不好"，分身却说"横按就是熬，手指头得练出茧才好使"——这句话听起来完全合理，但主人从没讲过任何练琴经验，更糟的是它摆出了一幅过来人的姿态。推演最大的代价不是答错，而是编造一个听起来对的主人。所以卡壳事件里除了 fabrication_risk，我们还会记一个 stance_error：姿态错误比细节编造更影响社交形象，也更难被发现。

为什么要在卡壳处出题？因为卡壳点就是分身的知识边界——在这里提问，单位信息增益最大。分身答得顺的地方说明卡片已经够了，再问是浪费用户时间。所以题目不是从题库里随机抽的，而是从这一场对话里长出来的：用户看到题目时能知道"这是分身今天真的卡住的地方"，代入感完全不同。

题目生成时还要过一道等赞许性校验：三个选项不能有明显的优劣之分。如果某个选项明显更"体面"，用户会选它而不是选自己真实的反应，这道题就白出了。校验方式是让打分器给每个选项的社会赞许度打分，极差过大就打回重写。

这一步是整套系统的发动机。分身在社交中遇到的每一个盲区，都会变成一道题回到主人面前；主人答完，分身下次就记住了。答错产生记忆，记忆提高下次答对率——这就是飞轮。而且它会自动加速：分身越强，社交聊得越深，遇到的情境越边缘，生成的题目也就越精微，用户不会一直在低级问题上消磨耐心。

⑤心灵感应：裁决与修正

心灵感应是数字分身的核心训练玩法，建卡之后终身进行。每一轮的规则是：系统出一道情境选择题，分身先当着主人的面公开作答，亮出选项、把握程度和理由；然后主人作答；程序比对两个答案。答对说明卡片已经准确，执行巩固；答错说明卡片有缺陷，程序判定缺陷属于哪种类型，再执行对应的修正。

先澄清：dim 是标尺，不是指令

题目选项上都带着一组维度向量，比如 {"O":-0.2,"C":0.3,"E":0.1,"A":0.4}。看到它容易产生一个误解：既然标了维度，是不是答完就要按这个数去改性格？不是。

dim 只用于测量，不用于修改。可以把它想成体温计上的刻度：体温计有刻度，但它不会改变你的体温。它的作用只有一个——用户做出选择后，程序用它算出这次选择落在哪些维度、往哪个方向走了多少（即观测位移 Δ），然后把测量结果分三处存放：

  • 写进世界书，作为一条先例或情境条目
  • 作为一条证据 Δ 记进该维度的证据队列（见第 ⑥ 章）
  • 记进成长层的 history，供日后的重演校验使用

至于分值动不动，取决于证据队列的累积和有没有够到阈值、重演校验过不过——跟这一次测量出来的数有多大无关。所以题目里出现 dim 不代表要改性格；恰恰相反，正是因为要把"改性格"这件事往后推、推到两道闸门之后，才需要在题目这一层先把结果量化和存证。

用户可以直接写下自己的回答

每道题都必须提供「都不太准，我自己说」的入口，用户可以直接写出自己的反应。这是常规入口而不是异常分支——实测下来它出现频率相当高，因为三个选项覆盖不了真人反应的分布。

自由回答的落点：

1. 原样写入世界书 —— 作为高可信度条目，因为这是本人原话
2. 不动分值 —— 没有落在选项上，拿不到 dim，算不出观测位移
3. 可选回填 —— 系统可以提议「你的回答最接近选项 B，是这样吗？」
   用户确认后，本轮才等价于选了 B，此时才有权重记入证据队列。
   这个提议必须由用户确认，不能自动映射——否则又变成系统替主人做判断。

三类裁决

判定依赖题目选项上标注的维度向量——有了它，程序能算出主人的选择与分身的预测相差多远、以及是否与当前性格方向相反，从而自动分类，不必让模型拍脑袋。

一致感：方向相同、只是细节偏差，比如分身和主人都想实质性地回应对方的倾诉，只是一个给建议、一个分享经历。这说明理论没错、记忆不够细，只巩固条目，分值不动。

盲区：分身缺少这类情境的记忆、只能按性格外推而答错，这是最常见的类型。修正动作是往世界书新增一条情境条目，同时分值最多微调一个维度 0.05——因为盲区根本不是性格错，给的额度必须小。

冲突：主人的选择与性格核心方向相反。此时不直接改分值，而是把这次的位移 Δ 作为一条证据记进该维度的队列，同时新增一条边界条目。设计理由：一次相反的选择完全可能来自特殊情境，单次反例不足以修正长期人格——要等队列里同向的证据累积够多才会动分值，具体机制见第 ⑥ 章。

一轮答案的五个落点：默认只写世界书

这里有个容易搞混的地方，需要单独说清楚：心灵感应的答案，默认只落在世界书；性格分值是被动的，不能直接被某一次作答修改。

世界书相当于分身的反应缓存——心灵感应主要是在扩充和修正这块缓存，让分身下次遇到同类情境有据可查。而底层的性格分值被两道闸门保护着：证据队列（同维度的证据累积够多才放行，见第 ⑥ 章）和重演校验（新卡重答历史题，一致率达标才落盘）。所以一次与性格方向相反的选择，只是在队列里多一条证据，不会动分值。

一轮答案的落点，按顺序：

1. 先例 —— 主人的选择无论对错，都记一条先例（事实层，只增不改不删）
2. 命中条目 —— 若本轮有世界书命中，按裁决结果巩固（+0.05）或降级（−0.08）
3. 新增条目 —— 盲区补情境条目；冲突补边界条目
4. 人格分值 —— 把本轮位移 Δ 记入该维度的证据队列（分身猜对时 Δ 为 0，等于不进账）。
                是否真的改分值，由第 ⑥ 章的队列机制决定，不在这里直接改
5. 成长层 —— rounds / matches / history / evidence 更新
用户点「都不太准」并直接说明时，分值一定不动。因为这种情况没有落在任何选项上，拿不到维度向量，算不出观测位移 Δ，程序上就不产生分值提案——只能写世界书。这不是缺陷：自由文本往往比选项信息量更大（能同时纠正事实、程度和姿态），代价只是无法直接换算成分值。

另外，选择题本身有固有局限：三个选项覆盖不了真人反应的分布。所以「都不太准」不该被当成异常分支，它是常规入口，实测出现频率相当高。

自洽的保障：四道防线

自洽的检查标准是这样的：性格分值是一套解释主人行为规律的理论，世界书里的先例是这套理论要解释的观测数据。修改后的分值如果能解释历史先例，修改就与数据相容，否则必须放弃。修改路径上一共有四道防线。

第一道是数值钳制。单次最多调整一个维度，且步长有上限，由代码强制截断。第二道是冲突拦截。反向选择不直接改分值，只作为一条证据进队列，累积够多才放行（见第 ⑥ 章）。第三道是重演校验。分值落盘之前，程序用调整后的卡片把历史题目重答一遍，一致率达标才通过；为避免小样本误判，历史题目不足十道时不做分值调整，只更新世界书；同时越近的先例权重越高，因为人的偏好本来就会随时间变化。第四道是先例只增。主人的真实选择只能新增、不能修改、不能删除。

第四道防线意味着矛盾会永久累积，那么内洽从哪来？答案是：当新证据与旧先例打架时，正确做法不是改掉旧记录，而是给两条都补上适用条件——拆成"无第三人在场时直说"和"有第三人在场时私下说"。内洽不来自删除矛盾，而来自把矛盾拆得更细——这也是为什么每条正文里都必须写明"什么条件下适用、什么情况下看反例 eXX"。

⑥性格的渐进演化

为什么性格也得能变

前面几章一直在讲怎么防止性格被改坏。但反过来也成立：性格必须能变，否则分身就永远停在主人建卡那一天。

这不是想当然。Roberts、Walton 与 Viechtbauer（2006）汇总了 92 项纵向追踪研究，结论是成年期人格仍在持续变化：尽责性、情绪稳定性在 20 到 40 岁显著上升，累积变化量超过一个标准差。更关键的一条是追踪时间越长，观测到的变化越大——说明人不是围绕某个固定值上下波动，变了就是变了，会保持下去。

但改性格比加记忆要危险得多：一条记忆错了只影响一次对话，性格错了会影响之后所有对话。所以下面这套机制只做一件事——让性格能变，但不能轻易变。

怎么变：攒够证据才动，一次只动一点

先说"位移"是什么。心灵感应的规矩是分身先当着主人的面作答、亮出选项和把握度，主人再作答，所以每一轮都会有两个答案。位移就是这两个答案差多少——具体说是主人所选选项的维度向量，减去分身所选选项的维度向量，得到的差值。

举个例：分身选了「私下指出」（宜人性 +0.2），主人选了「当场直接纠正」（宜人性 −1.0），这一轮宜人性的位移就是 −1.0 − 0.2 = −1.2，账本上记一笔 −1.2。反过来，如果两人选了同一个选项，位移就是 0，账本上一笔都不记。

为什么位移必须是"两者的差"，而不是"主人选了什么"。如果只记主人选了什么，那么主人在某个维度上每一次正常的选择都会朝同一侧累加，账本余额会一路涨过阈值，把分值一路推到 10 或 0——一个本来就外向的人会被越推越外向，这显然是错的。记"差"就完全不同：分身猜对了就没有差值，账本不动，性格稳定；猜错了才攒得出余额。账本记的是"分身错了多少"，不是"主人选了什么"——只有这样，整个系统才是能收敛的负反馈，而不是一路跑偏的正反馈。

每个维度各有一本账，记最近 20 次的位移。每轮心灵感应结束后，程序做三件事：

步骤做什么为什么
1 记账把这一轮的位移记到对应维度的账本上，只保留最近 20 次。猜对了记 0，等于没记只认最近的表现，很久以前的一次偶然不该一直影响现在
2 看余额把账本上的数加起来。余额不够 2.0，什么都不做；够了，就朝余额的方向把分值挪 0.1一次不算数，攒够了才算数
3 过校验挪完要用新分值重答一遍历史题。答得好就落盘，账本清零重来；答不好就退回去，账本留着继续攒防止改完之后解释不了主人过去的行为
就这么三条，没有例外，也没有其他通道。账户余额不够就什么都不发生，这是绝大多数轮次的常态——性格本来就不该经常变。

不同情况会怎么样

这套规则的好处是，不需要为每种情况单独写逻辑，它们在账本上的表现本来就不一样：

发生了什么账本余额结果
分身和主人选了同一个选项0什么都不发生。账本上不进账——猜对了说明卡片本来就准，没有要修的东西
只有一次选择了相反方向0.5 左右不动。可能就是那天心情不好
连续三次都选了相反方向2.0动 0.1。反复出现，说明之前的判断真错了
每次只差一点点，攒了十几次慢慢逼近 2.0动 0.1。这就是"人慢慢变了"
有时往左有时往右正负抵消，一直在低位不动。这不是系统的错，是这个人在这件事上本来就不稳定

表格第一行值得单独展开。分身猜对时，性格分值确实纹丝不动，但这一轮并不是白跑——它会做另外三件事：巩固命中的世界书条目（可信度 +0.05，上限 0.95），记一条先例，以及让成长层的一致率上升。所以"一致"的价值体现在记忆被加固和一致率这个指标上，而不是分值上。

其中有一类一致特别值钱：分身没有命中任何记忆、纯粹靠性格推演，却推对了。这说明主人在这类情境下的反应确实能被性格解释，但系统手上还没有对应的条目，下次遇到还得重新推一遍。这种情况的正确做法是把这次的推演结果固化成一条新条目写进世界书——既减轻以后的推理负担，也让这条记忆有了主人亲口确认的证据，可信度直接给到高位。这是"一致"这一支里唯一会往世界书里加东西的分支。

还有一点必须防住：三选一的题目瞎猜也有三分之一的命中率，所以一致的含金量取决于分身作答时自己报的把握度。把握度高还猜对，才是真的一致，值得巩固；把握度很低却猜对，很可能只是蒙的，条目只做最小幅度的加固，并且这类题目应该被优先重复出，直到分身能稳定答对为止。

注意最后一行：不是所有不一致都要去修正。如果主人自己在这个维度上就是摇摆的，硬去拟合一个"稳定值"反而是在编造。

两个补充入口

定期重测：每季度提示用户重做一次那 18 道锚定题，结果与当前分值按 0.3 新 / 0.7 旧 融合——以历史为主，避免一次作答就把分值带跑。顺带生成"性格体检报告"，让用户看到这一季的变化曲线。

用户手动改：用户可以在设置里直接拖分值。这听起来危险但必要，因为用户最了解自己。约束只有两条：改完必须通过重演校验，以及必须写变更日志，让改动可追溯、可回滚。

为什么必须慢慢来

一次只挪 0.1，而渲染档位的间隔大约是 2.0——也就是说要攒二十次才跨得过一个档位，中间的调整用户根本看不见（注入文本不变，分身行为也不变）。

这既是防抖保护，也带来一个问题：变化看不见，用户就觉得分身没在成长。所以每次落盘都要写变更日志，用"因—证—测"三段式把看不见的变化讲出来——变了什么、是哪几次作答支撑的、校验结果如何。看得见的成长才是养成感，否则用户只会觉得这个分身莫名其妙就变了。

⑦调整机制：每个元素谁能改、改多少

调整卡片一共用三种工具，分工明确。确定性代码负责规则与安全：归一化计分、步长截断、证据队列累加、条目合并判定、先例去重、停用降级、风格标签渲染、一致率统计，这些环节不允许模型插手，保证任何调整都有上限、有记录、可回滚。大模型负责语义判断：缺陷分类、题目与选项生成、世界书条目的关键词与正文构造、重演校验中的重新作答、知乎数据抽取、身份层提案撰写。用户确认负责事实：涉及主人身份的新增与删除都要走弹窗确认。

一句话概括：代码管规则与安全，模型管语义判断，用户管事实确认。每次调整都走"模型提案 → 代码把关 → 涉及事实时用户确认"这条链路落盘，分值类调整还要额外通过重演校验。
